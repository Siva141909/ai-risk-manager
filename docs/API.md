# API Reference — Phase 5A

Base path for all case endpoints: `/api/v1/cases`. Interactive OpenAPI
docs are auto-generated at `/docs` (Swagger UI) and `/redoc` when the
server is running (Phase 5A.12) — every endpoint below has a `summary`,
`description`, request/response schema, and documented error responses
there, generated directly from `src/api/schemas.py` and the route
decorators in `src/api/routers/`, never hand-duplicated.

## Authentication

None in Phase 5A — out of scope for this phase (see
`docs/BACKEND_ARCHITECTURE.md` §10). Do not deploy this API publicly
without adding it.

## `GET /health`

Service status and the static version labels of the frozen artifacts
this API serves. Never returns secrets/credentials.

```json
{
  "status": "ok",
  "app_version": "0.5.0-phase5a",
  "model_version": "phase2-xgboost-isotonic-calibrated-v1",
  "graph_config_version": "phase3-connected-components-min3-v1",
  "environment": "development",
  "llm_backend": "stub"
}
```

## `GET /api/v1/cases`

List cases from the deterministic development repository.

**Query parameters:**

| Param | Type | Notes |
|---|---|---|
| `risk_tier` | `LOW\|MEDIUM\|HIGH\|CRITICAL` | exact match |
| `graph_flagged` | `bool` | |
| `investigation_status` | `investigated\|not_investigated` | based on the in-process investigation cache |
| `start_dt` / `end_dt` | `int` | inclusive `TransactionDT` range — **this synthetic dataset has no real wall-clock dates** (established since Phase 2J), so range filtering is on the relative `TransactionDT` seconds column, not a calendar date |
| `limit` | `int`, 1-200, default 50 | |
| `offset` | `int`, default 0 | |

**Response:** `CaseListResponse` — `items` (list of `CaseSummaryResponse`), `total`, `limit`, `offset`.

## `GET /api/v1/cases/{case_id}`

Returns `CaseDetailResponse` — the deterministic `Case`: risk score/tier,
customer proxy info, graph evidence (if any). No `CaseGroundTruth`
field exists anywhere in this schema.

- `404 case_not_found` — no frozen validation/test-split score exists for this case.
- `400 malformed_case_id` — not a `CASE-<int>` shaped id.

## `GET /api/v1/cases/{case_id}/graph`

Returns `CaseGraphResponse` — the case's deterministic `graph_evidence`
plus a `nodes`/`edges` payload suitable for a graph-visualization
frontend, built by calling the existing, unmodified `get_graph_neighbors`
tool once per detected relationship type (no graph algorithm is
reimplemented in the API layer). Empty `nodes`/`edges` if the case has
no graph evidence.

## `GET /api/v1/cases/{case_id}/investigation`

Returns the existing `InvestigationReport` for this case if one has
already been produced (and is still in the process cache). **Does not
trigger a new investigation** — that's what the POST endpoint below is
for.

- `404 investigation_not_found` — no investigation has been run for this case yet.

## `POST /api/v1/cases/investigate`

Runs (or returns a cached) agent investigation.

**Request** (`InvestigateRequest`, `extra="forbid"` — an unrecognized
field, e.g. an attempted `ml_risk_tier` override, is rejected with 422):

```json
{
  "case_id": "CASE-3457202",
  "investigation_mode": "real_time"
}
```

or

```json
{ "transaction_id": 3457202 }
```

Exactly one of `case_id` / `transaction_id` is required.
`investigation_mode` defaults to (and currently only accepts)
`"real_time"`. `cutoff_dt` is optional and, if given, must exactly equal
the case's own trigger-transaction timestamp — see
`docs/BACKEND_ARCHITECTURE.md` §3 for why this is a validated
constraint, not an oversight.

**Response** (`InvestigationResponse`):

```json
{
  "case_id": "CASE-3457202",
  "transaction": {"transaction_id": 3457202, "transaction_dt": 12144110},
  "ml_risk_score": 0.0114,
  "ml_risk_tier": "MEDIUM",
  "graph_summary": { "...GraphEvidenceResponse..." },
  "investigation_report": { "...full InvestigationReport, src.agents.schemas..." },
  "evidence": [ "...convenience copy of investigation_report.evidence..." ],
  "recommendation": "investigate_further",
  "confidence": 0.5,
  "human_approval_required": true,
  "processing": {
    "request_id": "…", "llm_backend": "stub", "cache_hit": false,
    "investigation_mode": "real_time", "total_duration_ms": 41,
    "case_lookup_duration_ms": 1, "agent_duration_ms": 39
  }
}
```

**Latency:** near-instant with `RISK_MANAGER_LLM_BACKEND=stub`
(automated tests / CI); **20-60 seconds** with
`RISK_MANAGER_LLM_BACKEND=claude_agent_sdk` (real Claude investigation
— Phase 4's measured range across 12/12 evaluation cases). This is
synchronous by design; see `docs/BACKEND_ARCHITECTURE.md` §4.

**Errors:**

| Status | error_code | Meaning |
|---|---|---|
| 404 | `case_not_found` | |
| 400 | `malformed_request` | request schema violation (also auto-generated by FastAPI/Pydantic) |
| 400 | `unsupported_investigation_mode` | see §3 above |
| 503 | `llm_unavailable` | the configured LLM backend's transport failed (e.g. a session limit) |
| 500 | `agent_execution_failed` | an unexpected exception escaped the investigation graph |
| 504 | `investigation_timeout` | exceeded `RISK_MANAGER_INVESTIGATION_TIMEOUT_SECONDS` |
| 413 | `request_too_large` | body exceeds the configured size limit |

**Important:** a report with `validation_status="failed_human_review"`
is a normal **200** response, not an error — that is the frozen agent's
own fail-safe path (Phase 4N), preserved by this API exactly as
designed. See `docs/BACKEND_ARCHITECTURE.md` §6.

## Every error response shape

```json
{ "error_code": "case_not_found", "message": "...", "request_id": "..." }
```

Never a stack trace, file path, or line number — see
`tests/api/test_errors.py` for the tests that check this directly.

## Never exposed by any endpoint

`CaseGroundTruth` fields (`original_isFraud`, `synthetic_ring_id`,
`synthetic_abuse_type`, `synthetic_ring_role`, `legitimate_cluster_id`,
`legitimate_cluster_type`, `synthetic_entity_label`), internal prompts,
or any credential/API key. Enforced both by the response schemas never
having such a field and by an AST-based test confirming
`CaseGroundTruth` is never even imported under `src/api/`
(`tests/api/test_security.py`).
