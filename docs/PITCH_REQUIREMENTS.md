## OFFICIAL REQUIREMENT

Quoted verbatim from the live page:

**Public repository, pitch video, architecture — the full deliverable
list:** *"show your work (a public repo, a 5 minute pitch video, the
architecture)"*

**Pitch video length:** exactly **"a 5 minute pitch video"** — no
further format specification found anywhere on the page (no
resolution, platform, file format, or audio requirement stated).

**Architecture:** listed as a deliverable ("the architecture") with no
further detail on what form it must take (a diagram, a doc, a section
of the video — unspecified).

**Track 02 core requirement:** *"Build a working detector, verifier or
auto-responder for one class of loss, with measured precision and
recall on a held-out test set."*

**Track 02 evaluation bar:** *"Honest metrics including false-positive
cost. Strictly defense-only: anything offense-capable is disqualified."*

**Selection process:** *"Shortlisted builders go straight to a panel.
No aptitude test. No group discussion."*

**What the page does NOT say:** nothing on the official page specifies
what the pitch video itself should demonstrate, in what order, or with
what emphasis — no "lead with the problem," no "show don't tell," no
mention of narrating "what broke during development." **A secondary,
non-official aggregator site surfaced this kind of language during
research for this phase; it was checked directly against the live
official page (two targeted fetches, phrase-by-phrase) and confirmed
absent — it is not repeated here as if it were official guidance.**
This is exactly the kind of unverified claim this project has
consistently refused to launder into its own documentation (see
`docs/RAZORPAY_TRACK_02_COMPLIANCE.md` §17's same discipline).

**No new requirement, deadline, live-URL/deployment requirement, or
video-platform specification was found** — consistent with every prior
fetch this project has done (Phase 5C, Phase 6).

## INTERNAL JUDGE STRATEGY

Everything below is this project's own planning judgment, informed by
the absence of official format guidance, not a claim about Razorpay's
actual rubric — labeled as such throughout the rest of this phase's
documents (`docs/JUDGE_VIDEO_CRITERIA.md` carries the same label).
Because the official page is genuinely silent on structure, the burden
is entirely on this project to make good judgment calls about pacing,
emphasis, and content — documented explicitly rather than assumed.

Given no format constraint exists beyond "5 minutes," the internal
strategy adopted for this pitch (detailed in
`docs/PITCH_SCRIPT_V1.md`) is: problem → why ordinary detection misses
it → solution → live product → architecture → evaluation → AI
investigation → limitation → closing — a product story, not a
chronological build log, matching the explicit instruction for this
phase (Part 4) rather than any official Razorpay directive.
