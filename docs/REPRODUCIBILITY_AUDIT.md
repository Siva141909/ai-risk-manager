# Reproducibility Audit — Phase 6, Part 7

Simulated: a reviewer clones this repository onto a completely new
machine with nothing else installed. What actually happens, verified
against the real dependency graph (grep + direct code inspection), not
assumed from the README's own claims.

## 1. What can run immediately (zero setup beyond `pip install`/`npm install`)

**Backend:** `pip install -r requirements.txt` then `pytest -q` runs
**146 of 228 backend tests (64%) immediately**, with zero dataset, zero
API key, zero network call. These are the unit tests built on
in-memory/constructed fixtures (tool schemas, agent safety/case-
contract logic, RAG retrieval against the committed `docs/policy_documents/`
corpus, generator unit logic, threshold/cost-model math, most of
`src/models` on synthetic small inputs).

**Frontend:** `cd frontend && npm install && npm test` runs all
**36 frontend tests immediately** — every one uses a mocked `apiClient`
(`vi.mock`), zero backend, zero network. `npm run build` also succeeds
standalone (verified: clean `tsc -b && vite build` with no backend
running).

**API server:** `uvicorn src.api.main:app` (stub backend, default) —
**does NOT start successfully without generated data** (§2 below) —
this is the one place "can run immediately" is false and the README
does not make this limitation obvious.

## 2. What requires dataset acquisition + the full generation pipeline

**82 of 228 backend tests (36%) fail on a fresh clone** — not because
of a bug, but because they read from `data/synthetic/full/` and
`data/processed/*` (frozen ML scores, engineered features, the full
synthetic graph benchmark), all of which are correctly `.gitignore`'d
(`docs/RAZORPAY_TRACK_02_COMPLIANCE.md` §15 — this is intentional and
correct: the raw IEEE-CIS data has redistribution restrictions,
`docs/DATASET_ACQUISITION.md`) but are **not regenerated by any single
documented command** before this phase.

Affected: `tests/api/` (all 40 — `conftest.py`'s `client` fixture calls
`create_app()` → `load_tool_data_context()`, which reads
`data/synthetic/full/transactions.parquet` and
`data/processed/features.parquet` directly, no fallback), plus 5
integration test files (`test_dataset_validation.py`,
`test_graph_percolation_fixed.py`, `test_pipeline_leakage.py`,
`test_reproducibility.py`, `test_temporal_split_real_data.py`), plus
exactly **1 of 5** tests in `tests/unit/test_defense_only_audit.py`
(`test_only_one_mutating_route_exists_and_it_is_investigate`, the only
one that calls `create_app()`) and 3 tests in
`tests/unit/test_infrastructure.py`.

**To make all 228 pass, in order, starting from a fresh clone with only
the raw IEEE-CIS CSVs acquired** (`docs/DATASET_ACQUISITION.md`):

```bash
python -m scripts.generate_full_benchmark          # data/synthetic/full/
python -m scripts.prepare_features                 # data/processed/features.parquet
python -m scripts.train_baseline                   # data/processed/model_*.json, calibrator_*.joblib
python -m scripts.calibrate_and_threshold           # data/processed/risk_thresholds.json
python -m scripts.score_val_test_for_graph_fusion   # data/processed/val_test_ml_scores.parquet
python -m scripts.graph_benchmark_full              # data/synthetic/full/graph_benchmark_full_report.json
python -m scripts.graph_health_full                 # data/synthetic/full/graph_health_full.json
python -m scripts.ml_graph_ablation                 # data/processed/ml_graph_ablation_report.json
pytest -q                                            # now all 228 pass
```

**This exact sequence was NOT written down in one place anywhere in the
repository before this audit** — each script is individually documented
in its own phase's doc (`docs/GRAPH_BENCHMARK_FULL.md`,
`docs/ML_BASELINE.md`, etc.), but nothing consolidates the order. A
reviewer following only `README.md`'s "Environment" section
(`pip install -r requirements.txt && pytest -q`) would hit 82 failures
and reasonably conclude the project is broken, when the actual cause is
an undocumented multi-script setup sequence. **This is flagged as a
genuine reproducibility gap** — fixed in this same pass by adding the
consolidated sequence above to `docs/DEVELOPMENT_RUNBOOK.md` (a
documentation-clarity change only; no script, model, threshold, or
evaluation behavior was touched).

Total pipeline time: dataset generation (~72s) + feature engineering +
model training + calibration + graph benchmark (~similar order) — not
independently re-timed in this audit; each script prints its own
elapsed time when run.

## 3. What requires Claude/API access

**Nothing requires it to install, build, or pass the automated test
suite.** `RISK_MANAGER_LLM_BACKEND` defaults to `stub` — every
automated test (backend and frontend) uses `StubLLMClient` or a fake
client, zero network calls, zero cost, zero `ANTHROPIC_API_KEY`. Real
Claude (`claude_agent_sdk` backend) is needed only for a live demo run
and uses the local Claude Code CLI's own authentication — never a
separate key (`docs/AGENT_ARCHITECTURE.md` §3). `anthropic_api` backend
(needs `ANTHROPIC_API_KEY`) is implemented but genuinely never exercised
anywhere in this project (Phase 4/5C — honestly disclosed, not hidden).

## 4. What can run in stub mode

Everything except a genuinely AI-reasoned investigation: the full API
surface, the full frontend, the full demo flow (`docs/DEMO_FLOW.md`),
every automated test. Stub-generated reports are labeled `"backend":
"stub"` and every text field is prefixed `"STUB TEST:"` so they can
never be mistaken for real reasoning output (`docs/AGENT_ARCHITECTURE.md` §3).

## 5. Missing commands / gaps found this audit

| Gap | Impact | Fix |

## 6. Environment assumptions, stated exactly (not assumed compatible with anything else)

| | Verified value (this audit, this machine) | Where stated before this audit |
|---|---|---|
| Python | 3.14.3 | `README.md` ("Python 3.14.3, dependencies in `requirements.txt`") |
| Node | v22.22.0 | Nowhere — first documented in this audit |

| OS tested on | macOS (Apple Silicon) | `README.md` ("No GPU/CUDA dependency... Apple Silicon dev machine") |

**Not fabricated compatibility:** this project has only ever been run
on the one machine that built it. No claim is made here that Python
3.14/Node 22 are *required* minimums — only that they are the *verified*
versions, honestly distinguishing "tested on" from "guaranteed to work
on any earlier version" (neither `requirements.txt` nor `package.json`
pins a minimum Python/Node version).

## 8. Summary verdict

| Question | Answer |
|---|---|
| Can I install the project? | Yes, `pip install -r requirements.txt` + `npm install` — both succeed standalone |
| Can I run it without the private dataset? | Partially — 64% of backend tests and 100% of frontend tests, yes; the API server and the remaining 36% of backend tests, no |
| Can I run the demo? | Only after the full generation pipeline (§2) — the API server has a hard dependency on generated artifacts, no in-memory fallback exists |
| Can I run tests? | 146/228 backend + 36/36 frontend immediately; 228/228 backend after §2's sequence |
| Deterministic seeds? | Yes — one canonical seed (`configs/seed.yaml`, 42) for all dev/validation work, a second, distinct, documented seed (`20260824`) for the Track 02 held-out test — never reused, never silently changed |
